# Status

The Shoppie pilot, its harness (`docs/HARNESS.md`, `docs/PLAN_HARNESS.md`), durable state (`docs/DURABLE.md`, `docs/PLAN_DURABLE.md`), security / deployment (`docs/SECURE.md`, `docs/PLAN_SECURE.md`), the context layer and Gateway integration (`docs/CONTEXT.md`, `docs/PLAN_CONTEXT.md`), Runtime/Send-back (`docs/RUNTIME.md`, `docs/PLAN_RUNTIME.md`), and the Shoppie Copilot (`docs/COPILOT.md`, `docs/PLAN_COPILOT.md`) are implemented:

- **Known gap:** When `POST /api/requests/{request_id}/review` records support sign-off directly on the backend, it warns if the agent entrypoint is unreachable or times out rather than failing the sign-off; if the agent never resumed the request's thread, the decision stands on the backend while customer memory is not updated for that request.

- `backend/`: health, SQLAlchemy Core seed and repository (`backend/store.py`, supporting Postgres with the `undercover` schema and capped connection pools when `DATABASE_URL` is set, SQLite in offline tests, `prepare_threshold=None` on transaction pooler port `6432`, and `NullPool` when `AWS_LAMBDA_FUNCTION_NAME` is set), request list/detail (including `sent_back` archived decisions and `resume_heartbeat_at`), the request context, policies served section by section (`GET /api/policies` and `read_policy_section`, which records each section read on the request), policy-backed refund calculation (`POST /api/requests/{request_id}/refund` capped at ₹10,000.00 approval limit, tracking calculations in a `calculations` table per request attempt), read-only instructions for the queue and for a request, and claims manual section 14 deterministic validation (`backend/records.py`, `backend/money.py`): validates non-empty reason, section, and decided_by, requires approvals to have payout > 0 matching the attempt's calculation on file, and enforces payout = 0 on declines/referrals, refusing non-compliant records with HTTP 422 naming section 14. Idempotent agent operations start a waiting request, claim a sent-back request once (`POST /api/requests/{request_id}/take_sent_back`), heartbeat active resumes (`POST /api/requests/{request_id}/heartbeat`), store its complete recommendation (persisting `decided_by`, `manual_version`, `calculation`, and `decided_at`), record support sign-off atomically only while `waiting_for_agent_review` (`POST /api/requests/{request_id}/review` with `reviewed_by`, moving requests directly to `decided` on the backend and contacting the agent via `backend/agent_service.py` with warning logging on failure), send a recommended request back to the agent with a required note up to 1,000 characters (`POST /api/requests/{request_id}/send_back`), complete a reviewed request (`POST /api/requests/{request_id}/complete`), hold a request whose payment was refused by the Gateway (`POST /api/requests/{request_id}/hold`, `operation_id="hold_payment"`), or count a failed attempt. `backend/agent_service.py` invokes the agent once without retries either over HTTP (`POST {UNDERCOVER_AGENT}/invocations` with `Authorization: Bearer <UNDERCOVER_API_KEY>`, defaulting to `http://127.0.0.1:8080`, 10s timeout) or via `boto3.client("bedrock-agentcore").invoke_agent_runtime` when `UNDERCOVER_AGENT_RUNTIME` is set (5s connect, 20s read, unique session id >= 33 chars). `POST /api/runs` atomically locks `work_gate`, recovers runs silent for >= 5 minutes with `"The agent stopped answering"`, commits the new run before synchronously invoking `{"operation": "work_run", "run_id": ...}`, undoes refused/unreachable starts (`409`/`502`), and leaves timed-out starts running (`504`). `GET /api/runs/{run_id}`, `POST /api/runs/{run_id}/heartbeat`, `GET /api/runs/current`, `PUT /api/runs/{run_id}/todos`, `POST /api/runs/{run_id}/todos/{request_id}`, and `POST /api/runs/{run_id}/finish` keep run state and `stop_reason` current. The backend imports nothing from `agent/` or `runtime/`, exposing `handler = Mangum(app, lifespan="off")` with lazy `Store()` initialization. The agent's standalone API schema is published at `GET /api/agent/openapi.json` with exactly 6 operations. Every agent route requires `X-API-Key: <UNDERCOVER_API_KEY>`, while support-handler actions reject requests carrying the agent key. `backend/context_files.py` reads plans and document versions directly from `context/` during seeding without importing `context.files`. `npm run seed` rebuilds the database with 9 requests (including `REQ-7901` from `data/security/customer_orders.json`).
  - **Backend additions for Copilot & Benchmarks:** Support handlers (`HND-01` Dana Whitfield senior / unlimited, `HND-02` Marcus Oyelaran up to ₹10,000.00, `HND-03` Priya Nair senior / unlimited) via Cognito JWT claims or signed `X-Handler-Id` header locally; single-use HMAC-signed ephemeral handler tokens (`backend/handlers.py`) verified by `HandlerDep`; queue overview + pilot targets (`GET /api/copilot/overview`), settings (`GET /api/copilot/settings`), handler profile (`GET /api/copilot/me`), conversation CRUD (`POST/GET /api/copilot/conversations`, `/turns`, `/turns/{turn_id}/confirm`, `/turns/{turn_id}/stop`, `/steps`, `/turn_complete` strictly rejecting `X-API-Key` on handler endpoints and requiring it on Copilot callback endpoints); and quality benchmarks (`POST /api/quality_runs`, `GET /api/quality_runs/current`, `GET /api/quality_runs/{benchmark_id}`). `backend/agent_service.py` dispatches Copilot turns and sign-off confirmations to `UNDERCOVER_COPILOT` (default `http://127.0.0.1:8081`) or `UNDERCOVER_COPILOT_RUNTIME`.
- `context/`: the context layer MCP server (`undercover-context`), serving 7 read-only FastMCP tools (`lookup_term`, `describe_fields`, `get_plan`, `get_claim_rules`, `search_reference_data`, `search_documents`, `read_section`) over streamable HTTP at `/mcp` and `GET /health` on port `8006` (`dev:context` or containerized with `HOST` / `PORT`, disabling DNS-rebinding host checks outside loopback), or via AWS Lambda (`context.server.handler` wrapped with `Mangum`). The 7 data governance files in `context/` are read once at startup, splitting markdown into numbered sections while stripping front matter and attaching source metadata (`file`, `system`, `owner`, `reviewed`) to every answer. `check:context` verifies isolated execution with the `context` dependency group.
- `azure/`: Azure Container Apps Option B deployment assets (`.dockerignore`, `Dockerfile.backend`, `Dockerfile.agent`, `Dockerfile.copilot`, `Dockerfile.context`, `main.bicep`, `README.md`) targeting four containers (`shoppie-backend`, `shoppie-agent`, `shoppie-copilot`, `shoppie-context`) backed by Azure Container Registry and Azure Database for PostgreSQL - Flexible Server (`?sslmode=require`).
- `agent/` and `runtime/`: decoupled completely from `backend/` (`agent/models.py`, `agent/instructions.py`), with zero import-time side effects or connection creation. The queue agent (`agent/queue.py`, `run_queue(run_id, cap)`, `work_run(run_id)`) verifies `GET /api/runs/{run_id}` is running, sends 1-minute heartbeats to `POST /api/runs/{run_id}/heartbeat`, uses LangChain's `create_agent` to plan a run as a to-do list and hand each request to the request agent with `work_request`, after first finishing any signed-off requests still paused and resuming any mid-flight requests (skipping resumes heartbeat-active within 5 minutes), and reports run completion only for its own `run_id` to `POST /api/runs/{run_id}/finish`. Code enforces the cap and ticks the to-do list, and an `after_agent` middleware sends the agent back if it misses a waiting request within the cap. The request agent (`agent/main.py`) supports dual routing via `agent/routes.py` (Direct via `agent/direct.py` or AgentCore Gateway via `agent/gateway.py` with SigV4 signing): model tools read request context from state and omit the request ID from model inputs; tool refusals from the Gateway or application are recorded as clean `refusal` progress steps while continuing work; if payment completion is refused by the Gateway, the request is placed on hold (`hold_payment`) and keeps its graph paused at `approval` waiting for support review. Sent-back resumes reset `model_calls` and decision state, append the reviewer note, and pause again at `approval`. Customer memory integration (`agent/memory.py`) connects to AgentCore Memory via `AgentCoreMemoryStore` from `langgraph-checkpoint-aws` when `UNDERCOVER_MEMORY_ID` is set: upon completing a signed-off request (after `complete`), a `remember` node saves two events (request message and decision record) under customer actor ID and request session ID, omitting customer story and raw documents, and skipping security-flagged requests or evaluation copies. When enabled outside evaluations, the agent has a `search_memory` tool to recall earlier requests and facts restricted to that customer's namespace, while excluding the current request's summary; AgentCore connection failures are handled gracefully (warnings on save, refusals on search). It is a hand-written synchronous LangGraph `StateGraph` (`screen`, `agent`, `tools`, `decide`, `approval`, `complete`, optional `remember`) compiled with a lazy `psycopg_pool.ConnectionPool(..., prepare_threshold=None)` `PostgresSaver` when `DATABASE_URL` is set or `InMemorySaver` in tests: evaluation copies finish without pausing at `approval`. `agent/entrypoint.py` exposes `app = BedrockAgentCoreApp()` on port `8080` (`runtime/main.py` for AgentCore Runtime), initializing lazily on the first invocation (including `health`), reseeding `random` and fetching `AGENTCORE_CREDENTIAL_*_NAME` secrets from AgentCore Identity on Runtime, requiring `Authorization: Bearer <UNDERCOVER_API_KEY>` off-Runtime except for `health`, validating payloads strictly (`health`, `work_run`, `resume_request`), and running work on background threads tracked via `add_async_task` / `complete_async_task` so `/ping` reports `HealthyBusy` while active.
  - **Shoppie Copilot agent (`agent/copilot_graph.py`, `agent/copilot_tools.py`, `agent/copilot_memory.py`, `agent/copilot_entrypoint.py`, `runtime/copilot_main.py`):** Synchronous LangGraph `StateGraph` (`recall` -> `assistant` -> `tools` -> `confirm_sign_off` -> `save_memory`) using ephemeral handler tokens against backend endpoints (never saving bearer tokens in checkpoints or handler memory), connecting read-only policy/context tools to `Target.CONTEXT` (`gateway` or `direct.from_environment()`), storing handler memory per `(handler_id, "preferences" | "facts")` via `UNDERCOVER_COPILOT_MEMORY_ID` or Postgres/InMemory store, enforcing the ₹10,000.00 authority ceiling on `prepare_sign_off`, and interrupting at `confirm_sign_off` until confirmed (`Confirm sign off` / `Cancel`). Served on port `8081` (`agentcore/agentcore.json` `"copilot"` runtime + `agentcore/cdk/lib/cdk-stack.ts` `UNDERCOVER_COPILOT_MEMORY_ID`).
  - When `LANGFUSE_SECRET_KEY` and `LANGFUSE_PUBLIC_KEY` are set, each request's work is traced in one Langfuse session named after the request and its thread. Model and transport calls are retried automatically, and a single attempt is capped at 30 model calls. The default model is DeepSeek V4.1 Flash with low reasoning effort; `MODEL_NAME` overrides it (`COPILOT_MODEL` overrides for Copilot). `uv run -m agent --cap 5` starts a capped run, and `uv run -m agent REQ-7001` works one request.
- `dashboard/`: the support queue (`Waiting`, `In progress`, `Needs review`, `Sent back`, `Left for support`, `Decided`) with a "Requests to work" cap and Initiate processing button, plus the collapsible **Shoppie Copilot** chat sidebar (`dashboard/src/CopilotSidebar.tsx`, `CopilotMessage.tsx`, `copilotApi.ts`) with handler switcher locally, conversation history / `+ New chat`, starter prompts, live step timelines, clickable `REQ-xxxx` links, and interactive `ConfirmationCard` (`Confirm sign off` / `Cancel`). The run panel shows the to-do list, `stop_reason` (`REASON STOPPED`) when stopped, and the summary. The request detail shows archived `sent_back` decisions with notes/timestamps alongside the current recommendation, the progress timeline (including `sent_back` and `signed_off` steps), the complete decision record with line-by-line payout calculation breakdown (`CalculationTable`), and **Context used** (`ContextUsed`). Support handlers can either sign off (`Record support review` with `Reviewed by`) or send a recommended request back (`Send back` with required `Sent back by` and 1–1,000 character note, excluding Security check holds and left-for-support requests). The instructions panel shows the queue and request instructions, read only.
- `e2e/`: Playwright tests (`dashboard.spec.ts`, `runtime.spec.ts`, `copilot.spec.ts`) plus `e2e/agent_stand_in.js` (`:8003`) and `e2e/copilot_stand_in.js` (`:8004`).
- `data/`: synthetic Shoppie customer, order, and support request records, including clearly labeled synthetic follow-ups, photo, packing, delivery and carrier evidence for every request, and a fulfillment timeline (plus shipment tracking once dispatched) on every order. `data/security/customer_orders.json` provides `REQ-7901` to test the hidden-instruction check. Food and perishable cases are limited to the leafy greens cancellation and the missing bread report; the food-safety guardrail is covered by a unit test fixture.
- `docs/`: Shoppie's sample shopping, cancellation, and returns policies, which the agent reads section by section.
- `data/evals/`: reference decisions kept separate from agent-readable data.

Agent recommendations support review; the product does not execute real customer or order actions. The dashboard displays INR values and IST times for the synthetic records.

## Running it

Run `uv sync` and `npm install` at the repository root. Start the local Postgres container (`shoppie-postgres` on `127.0.0.1:5432`, with `DATABASE_URL=postgresql://postgres:postgres@127.0.0.1:5432/postgres` and `UNDERCOVER_API_KEY` in `.env`), run `npm run seed` to reset the `undercover` schema, and run `npm run dev` to start the backend (`:8000`, loading `.env`), the request/queue agent AgentCore app (`:8080`, loading `.env`), the Copilot AgentCore app (`:8081`, loading `.env`), the context MCP server (`:8006`), and the dashboard (`:5173`). `npm run build` builds the dashboard into `dashboard/dist`, which `backend.main:app` serves at `/` on a web server such as Render. Start a run from the dashboard or Copilot sidebar, or with `uv run -m agent --cap 5` while `npm run dev` is running. For trials on the real model, reseed first and cap the run at five requests.

The Linux Python 3.12 Lambda deployment package (`backend/`, `data/`, `dashboard/dist/`, and `--only-group server` wheels including `boto3`) produces a zip of 38 MB (105 MB uncompressed), inside AWS Lambda's 50 MB direct upload and 250 MB unzipped limits.
