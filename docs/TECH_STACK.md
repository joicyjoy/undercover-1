# Tech stack

- `backend/`: FastAPI and SQLAlchemy Core (`backend/store.py`, `backend/handlers.py`), using Postgres (the `undercover` schema, with `pool_size=2, max_overflow=2`) when `DATABASE_URL` is set or SQLite in tests. Every API operation has an `operation_id`, a one-line docstring and no optional inputs or query parameters. It stores requests with their attempts, steps (including context `sources` and `sent_back` events), archived `sent_back` decisions, `resume_heartbeat_at`, current recommendation and review (including `reviewed_by` and `reviewed_at`), runs with `last_heartbeat_at`, `stop_reason`, to-do lists, and summaries, the single-row `work_gate` lock guaranteeing at most one active run (recovering runs silent for 5 minutes with `"The agent stopped answering"`), and Copilot tables (`benchmarks`, `copilot_conversations`, `copilot_turns`, `copilot_steps`, with a 20-minute stale-turn timeout `STALE_COPILOT_SECONDS = 1200`). `backend/agent_service.py` invokes the request agent once without retries via `call_agent`, and invokes the Copilot runtime via `call_copilot` (with transient `ConflictException` retry recovery and deterministic `conversation_id`-scoped AgentCore session IDs) over HTTP (`UNDERCOVER_COPILOT`, default `http://127.0.0.1:8081`) or `boto3` `bedrock-agentcore` (`UNDERCOVER_COPILOT_RUNTIME`). Ephemeral short-lived HMAC-SHA256 bearer tokens (`backend/handlers.py`) bind Copilot actions strictly to the signed-in support handler (`HND-01` Dana Whitfield / `HND-02` Marcus Oyelaran, resolved from Azure Entra `X-MS-CLIENT-PRINCIPAL-*` headers or dev `X-Shoppie-Handler`). Policies are served section by section, refunds are calculated in `backend/refunds.py`, decision records follow claims manual section 14 enforced by `backend/records.py`, and quality benchmark runs are exposed under `/api/quality_runs*` (with no `"eval"` path segments). `backend/context_files.py` reads context layer plans and document versions during seeding. `npm run seed` rebuilds the database. The product recommends support outcomes; it does not execute cancellations, returns, or refunds.
- `context/`: the context layer MCP server (`undercover-context`), serving 7 read-only FastMCP tools (`lookup_term`, `describe_fields`, `get_plan`, `get_claim_rules`, `search_reference_data`, `search_documents`, `read_section`) over streamable HTTP at `/mcp` on port `8006` (`dev:context`), or via AWS Lambda (`context.server.handler` wrapped with `Mangum`) with DNS rebinding protection disabled. The 7 data governance files in `context/` are read once at startup, splitting markdown into numbered sections while stripping front matter and attaching source metadata (`file`, `system`, `owner`, `reviewed`) to every answer.
- `agent/` and `runtime/`: decoupled completely from `backend/` (`agent/models.py`, `agent/instructions.py`) with zero import-time side effects or connection creation. The queue agent (`agent/queue.py`, `run_queue(run_id, cap)`, `work_run(run_id)`) confirms the run is running via `GET /api/runs/{run_id}`, sends 1-minute heartbeats to `POST /api/runs/{run_id}/heartbeat`, uses LangChain's `create_agent` to plan a run as a to-do list, finishes any paused sign-offs, works waiting and sent-back requests (skipping resumes whose heartbeat is under 5 minutes old), and closes only its own `run_id`. The request agent (`agent/main.py`, `run_request(request_id, thread_id)`) supports dual routing via `agent/routes.py` (`agent/direct.py` or `agent/gateway.py` with SigV4 signing) and customer memory via `agent/memory.py` (`AgentCoreMemoryStore`), saving memory only after `complete` when signed off (or skipping evaluation copies and security holds). Sent-back resumes reset decision state and `model_calls`, append the reviewer note, and pause at `approval` again until confirmed or sent back. The hand-written synchronous LangGraph `StateGraph` (`screen`, `agent`, `tools`, `decide`, `approval`, `complete`, optional `remember`) compiles with a lazy `psycopg_pool.ConnectionPool(..., prepare_threshold=None)` `PostgresSaver` when `DATABASE_URL` is set or `InMemorySaver` in tests. `agent/entrypoint.py` exposes `app = BedrockAgentCoreApp()` on port `8080` (`runtime/main.py` on AgentCore Runtime). Beside it, Shoppie Copilot (`agent/copilot_graph.py`, `agent/copilot_tools.py`, `agent/copilot_memory.py`, `agent/copilot_entrypoint.py`, `runtime/copilot_main.py`) runs a hand-written synchronous LangGraph `StateGraph` (`load_memory`, `model`, `tools` `ToolNode`, `confirm_sign_off` using `interrupt()` / `Command(resume=...)`) with 19 tools bound via `ToolRuntime.context`, routing context tools strictly via `Target.CONTEXT` and handler-scoped memory (`UNDERCOVER_COPILOT_MEMORY_ID`) to `/handlers/{handler_id}/preferences` and `/facts`. `agent/copilot_entrypoint.py` exposes `BedrockAgentCoreApp()` on port `8081` in local dev (`dev:copilot`) and port `8080` on Runtime/Azure. Both entrypoints handle background daemon threads via `add_async_task` / `complete_async_task` so `/ping` reports `HealthyBusy` while active. Default model: `deepseek/deepseek-v4.1-flash` with low reasoning effort (`MODEL_NAME` overrides).
- `dashboard/`: React, Vite and TypeScript. Includes the support queue (showing `Sent back`), run progress (displaying `stop_reason` when stopped), request details with previous `sent_back` decision cards, decision calculation breakdown (`CalculationTable`), refusal chips, **Context used** (`ContextUsed`), the **Send back** form alongside sign-off, and the persistent collapsible **Shoppie Copilot** sidebar (`CopilotSidebar.tsx`, `CopilotMessage.tsx`, `copilotApi.ts`) with `localStorage` state persistence, dev handler switcher, 1s live polling while working, expandable tool step cards, formatted markdown with clickable `REQ-XXXX` navigation links, and sign-off `ConfirmationCard`.
- `e2e/`: Playwright tests (`dashboard.spec.ts`, `runtime.spec.ts`, `copilot.spec.ts`) plus Node stand-ins `e2e/agent_stand_in.js` (`:8003`) and `e2e/copilot_stand_in.js` (`:8004`) testing concurrent run `409`, `stop_reason`, send-back + re-evaluation, sign-off completion, Copilot sidebar persistence, live steps, request links, sign-off confirmation approve/cancel, direct send-back, and Marcus over-limit refusal.
- `data/`: Shoppie's synthetic customer, order, and support request data, along with enterprise context files in `context/`. The agent never sees `data/evals/`.

Python 3.12 with uv, all in the root `pyproject.toml`. Node.js 24.15.0, pinned in `.nvmrc`. `.env` holds `OPENROUTER_API_KEY`, `UNDERCOVER_API_KEY`, `DATABASE_URL`, and optional `MODEL_NAME`, `UNDERCOVER_GATEWAY_URL`, `UNDERCOVER_MEMORY_ID`, `UNDERCOVER_CONTEXT`, `UNDERCOVER_AGENT_RUNTIME`, `LANGFUSE_SECRET_KEY`, `LANGFUSE_PUBLIC_KEY`, and `LANGFUSE_BASE_URL`.

## Security

- The agent sends `X-API-Key: <UNDERCOVER_API_KEY>` on every backend call, read at send time. The backend checks it with `secrets.compare_digest` in FastAPI dependencies that read `request.headers`, so no key parameter appears in any OpenAPI operation. Agent-only routes require it (`401` otherwise), shared reads accept the dashboard or a valid key, support-handler actions (`review_request`, `send_back_request`, `start_run`) refuse any call carrying `X-API-Key`, and `GET /api/health` is open. Off Runtime, `agent/entrypoint.py` requires `Authorization: Bearer <UNDERCOVER_API_KEY>` on every operation except `health` (`401` otherwise); on Runtime, AWS authorizes invocations and secrets come from AgentCore Identity.
- The request graph starts with `screen`: customer-written fields go to `openai/gpt-6-luna` at `reasoning_effort="none"` (or `MODEL_NAME`) with Structured Outputs, up to 3 attempts. Flagged requests get a held recommendation citing `"Security check"`, skip memory, and cannot be sent back.
- `GET /api/agent/openapi.json` publishes only the six request-agent operations, with no `servers` entry.
- `calculate_refund` refuses any amount over `MAX_REFUND_LIMIT` (₹10,000.00) with a `403`.

## Deployment

- `backend/` and `agent/` never import one another. `server` group holds the backend's packages (`boto3`, `fastapi`, `httpx`, `mangum`, `openrouter`, `psycopg[binary]`, `pyjwt[crypto]`, `sqlalchemy`, `uvicorn`), verified by `npm run check:server`; `context` group is verified by `npm run check:context`; `runtime` group holds the agent's packages (`bedrock-agentcore`, `boto3`, `httpx`, `langchain`, `langchain-mcp-adapters`, `langchain-openai`, `langfuse`, `langgraph-checkpoint-aws`, `langgraph-checkpoint-postgres`, `mcp`, `psycopg-pool`, `psycopg[binary]`, `python-dotenv`), verified by `npm run check:runtime`.
- The backend creates and locks runs in PostgreSQL/SQLite, then makes a single non-retried call (`POST {UNDERCOVER_AGENT}/invocations` with Bearer token, 10s timeout; or `boto3.client("bedrock-agentcore").invoke_agent_runtime` with 5s connect, 20s read, >=33-char session ID when `UNDERCOVER_AGENT_RUNTIME` is set). If the agent refuses or cannot be reached (`did_not_take`), the backend immediately undoes/stops the run with `stop_reason` and returns `409`/`502`; if timed out or cut off (`uncertain`), the backend leaves the run `running` (`504`) so reload checks whether it started.
- **Render (live):** one web service runs `backend.main:app` on `$PORT` beside `agent.entrypoint:app` on port `8080`, serving `dashboard/dist` at `/`, backed by Render Postgres (`undercover` schema). Build: `uv sync --frozen --only-group server --only-group runtime && npm ci --ignore-scripts && npm run build`. Environment: `DATABASE_URL` (internal connection string), `UNDERCOVER_AGENT=http://127.0.0.1:8080`, `OPENROUTER_API_KEY`, `UNDERCOVER_API_KEY`, and optional `MODEL_NAME` and Langfuse keys.
- **Azure Container Apps (`azure/`, Option B):** four containers (`azure/Dockerfile.backend` on port `8000` external HTTPS, `azure/Dockerfile.agent` on port `8080` internal-only, `azure/Dockerfile.copilot` on port `8080` internal-only running `agent.copilot_entrypoint:app`, `azure/Dockerfile.context` on port `8006` internal-only with `GET /health` and DNS-rebinding protection disabled outside loopback) provisioned with Azure Container Registry and **Azure Database for PostgreSQL – Flexible Server** (`?sslmode=require`; backend, agent, and copilot disable prepared statements on transaction pooler port `6432`) via [`azure/main.bicep`](file:///Users/joicy/projects/undercover/azure/main.bicep). Uses [`agent/direct.py`](file:///Users/joicy/projects/undercover/agent/direct.py) and `UNDERCOVER_COPILOT` over internal HTTPS + Bearer keys.
- **AWS Lambda + AgentCore Runtime (`agentcore/`):** backend handler `backend.main.handler` (`Mangum`, `NullPool`, `prepare_threshold=None`) invokes the deployed AgentCore Runtimes (`UNDERCOVER_AGENT_RUNTIME` running `runtime/main.py`, `UNDERCOVER_COPILOT_RUNTIME` running `runtime/copilot_main.py`) using IAM permissions (`runtime/policy.json`) and Identity credentials (`OPENROUTER_API_KEY`, `UNDERCOVER_API_KEY`, `DATABASE_URL`), plus `UNDERCOVER_COPILOT_MEMORY_ID` passed via CDK. Context server runs at `context.server.handler`.
